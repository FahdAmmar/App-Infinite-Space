# Known limitations

Behavior that is intentionally or currently limited. Back to the [README](../README.md).

## Known limitations

- **Everything is local to one browser profile.** Clearing site data, using another browser or device, or private windows that discard storage removes it. Export a workspace from its ⋯ menu to keep a copy; there is no automatic or scheduled backup, so an export is only as fresh as the last time you made one.
- **Two tabs on the same workspace**: when one tab saves a change, the other pauses saving and asks you to load the latest version or keep its own. This relies on `BroadcastChannel`; without it the old behavior applies (last tab to save wins). If both tabs save within the same moment, the later write still wins, and there is no live sync. Undo history is per tab and not restored after a reload.
- **Saving during tab close is best effort.** Browsers do not guarantee that an asynchronous write finishes while a page is closing. The app starts the write immediately and asks for confirmation when changes are pending, but a crash or a forced close can lose the last fraction of a second of work.
- **Undoing the deletion of an image card** works while the image file still exists. The cleanup keeps unused files for 24 hours, so undo works across a long session but an image removed and left unused for more than a day cannot be restored by an old tab; the card then shows "Image unavailable".
- If IndexedDB is blocked, images are kept in memory only (and are lost when the tab closes), and canvases fall back to `localStorage` (about 5 MB). The app tells you once when images fall back.
- **Restoring a recovery copy is best effort.** Data written by a newer version is read with today's rules, so fields the newer version added are dropped and damaged cards are skipped. A restored canvas becomes a new workspace named "Recovered workspace"; the copy itself is kept until you delete it. Restoring a copy of the workspace list only re-adds workspaces that are missing.
- **Export files are plain JSON with images as Base64**, so images take about a third more space in the file than in the browser. A file above 256 MB is refused on export and import. An export does not include undo history, the minimap setting, or UI preferences.
- The storage figure comes from the browser's own estimate (rounded, and covering all of this site's data), and "Protect my data" is a request that the browser may decline.
- Groups cannot be nested, cannot be connected, and an overlapped card joins a group only if its center is inside. Resizing a group re-evaluates every card on the canvas.
- Reattaching a connection is a pointer gesture only; with the keyboard, delete it and use *Connect to…*. Two connections between the same pair in opposite directions overlap when both use the default sides.
- **Copy and paste is held in the tab's memory.** It survives opening another workspace in the same tab, but not a reload, and not another tab. Copying also writes a short sentence ("InfiniteSpace: 3 items copied") to the system clipboard so an older screenshot there does not win when you paste; if the browser refuses that write, an older image in the system clipboard can be pasted instead of the cards. Image cards pasted into another workspace share the stored picture with the original, and the picture is kept while any workspace uses it.
- **Find** looks at text, file names, links, and tags, not at what an image shows. It selects one match at a time rather than highlighting them all, and the shortcut does not open the browser's own find, so use the browser menu for that. While you are typing in a card, `Ctrl/⌘+F` still opens the browser's find.
- There is no way to lock a card, and no guide lines while dragging. Align and distribute use each card's measured size, and a card moved or pasted inside a group's frame joins that group (the same rule as dragging).
- Link cards show only what you type: no page title, description, or icon is fetched.
- **A workspace holds at most 5,000 items and 10,000 connections** (see Verification). Zoomed all the way out with thousands of cards visible, panning is noticeably slower; there is no level-of-detail mode.
- Nodes lag the pointer by up to the 3 px drag threshold at the start of a drag (an intentional guard against accidental drags).
- Double-click creation needs a mouse or a double-tap; use the dock tool, then tap the canvas, on touch devices.
- Two tabs editing at once follow "last writer wins" at the workspace-list level.
- No Arabic web font is bundled; Arabic text renders in the system font (it displays correctly and right-to-left inside nodes and inputs). The interface itself is English-only and left-to-right.
- **Pasting copied cards needs permission to write to the clipboard.** The app writes a short marker sentence there when you copy cards. If the browser refuses (some embedded or insecure pages), `Ctrl/⌘+V` does not paste the cards, and whatever text was already on the clipboard becomes a card instead. The browser flow grants the permission explicitly.
- **The command palette** opens with `Ctrl/⌘+K` or the button in the top bar. The tag filter and the focus branch fade cards rather than hiding them, and neither is saved.
- **Presentation order follows position only** (rows, then left to right); there is no way to reorder slides, add speaker notes, or number them, and a right-to-left reading order is not used. Only groups are slides; a canvas without groups cannot be presented. Panning during a presentation is allowed, and a toast message can briefly cover a slide. **Templates** are in English with fixed layouts and placeholder text, and a template is built once at creation (the library is not editable).
- **Text paste is capped** at 20 cards per paste and 5,000 characters per card. **Image compression** runs in the browser when a picture is added: if the browser cannot encode WebP, or the saving is under 10%, the original is stored; animated pictures and AVIF are never recompressed, and pictures already on a canvas are not.
- **Browser flows ran only in headless Chromium.** The Phase 7, 8, 12, 15 and 16 flows and the quick-wins flow pass there, including the tab banner's position on a desktop and a phone screen. Not tried: a visible browser, real GPUs, Safari, Firefox, and real devices.
- **Deployment to Vercel has not been tried.** The configuration passes `npm run deploy:check` and a local emulation of the routing, but the live site, its headers, and the Content-Security-Policy (shipped in report-only mode) were never exercised in a browser. See [DEPLOYMENT.md](DEPLOYMENT.md).
- **Browser data belongs to one web address.** A preview address, the production address, and a custom domain each have their own empty storage; use Export and Import to move workspaces.
- Only Chromium was used for automated browser verification; Safari, Firefox, and real devices were not tested. Touch behavior was checked with Chromium's device emulation (coarse pointer, touch taps), not on a real phone or tablet; the phone layout (zoom toolbar, properties panel, action bar) was checked by geometry and screenshots at 390 px.
- **The editor title is still short on a phone.** At 390 px the title has about 68 px of text room (it was 44 px), enough for roughly eight Latin characters, so most names are cut with an ellipsis; the rename field and the dashboard show the full name.
- **Touch fields are 16px, but text size changes slightly when you edit a card on a touch device.** Card text is shown at 15.2px and its editor is 16px (iOS Safari zooms the page for anything smaller). This was checked with Chromium's emulation only, not on an iPhone, and so was the claim that the zoom no longer happens.
- **Safe areas are handled with CSS variables, but only simulated.** The floating bars add `env(safe-area-inset-*)` through `--safe-*` variables, and the browser check moves them with a fake inset. Chromium has no real notch, so nothing was checked on an iPhone.
- **Backup folder (Chromium only).** The permission to write to the folder is usually lost between sessions; the Data dialog then shows *Reconnect folder* and automatic backups pause until you click it. Each workspace has one file with a stable name: renaming a workspace creates a new file and leaves the old one, and deleting a workspace leaves its file. Automatic backup runs every 5 minutes while the tab is visible and writes only workspaces changed since the last backup. Keeping the folder choice across a reload could not be tested automatically (reading a folder handle back from IndexedDB crashes the headless browser used here), so check it by hand in Chrome. Firefox and Safari fall back to downloading one file per workspace.
- **Offline mode was checked in Chromium only.** The service worker precaches the built files, so the editor and dashboard reopen without a connection. The update prompt (a new version waits until you click *Reload*) is covered by a unit test, not by a real second deployment. Whether Vercel serves `/sw.js` with `max-age=0` was checked in the config only, not on a live site. Safari may evict site data for sites not visited for a while, which is why backups matter.
- **The 3D backdrop is skipped** on devices reporting two cores or fewer, or 2 GB of memory or less (also on phones and with reduced motion or data saving). The thresholds are a guess, not measured on real low-end devices.
- **The background effect was only run in headless Chromium with software WebGL.** Frame rate, battery use, and look on real GPUs, Safari, Firefox, and low-end devices were not measured. If it feels heavy on your machine, turn it off with the sparkle button.
- **Border Beam** needs `offset-path: rect()`. It is hidden where that is unsupported, but only Chromium was checked.
- No screen reader was used. The app provides labels, descriptions, live regions, and keyboard paths, and automated checks pass, but real announcements are unverified.
- **Card links work only in the browser that holds the data.** `?card=` opens a card in the same browser profile; sending the link to someone else, or opening it on another device, shows an empty or different workspace.
- **The read-only HTML page is a picture of the moment you save it.** It does not update, shows PNG, JPEG, WebP and GIF pictures only (others are left out and counted in the message), and is refused above 64 MB of pictures. Its drawing of connections is a simplified version of the app's.
- **Snippets leave out image cards**, because unused image files are removed automatically and a snippet would later show an empty picture. They live in this browser's `localStorage` (30 at most, 200 KB each), are named after the first card, and cannot be renamed (delete and save again).
- **Search in all workspaces** reads workspaces from browser storage on the first search, which can take a moment with very large ones; unreadable workspaces are skipped silently, and it finds text, links and tags, not what pictures show.
- **The focus branch follows the arrow direction.** Cards joined only by a shared ancestor (siblings) are not in the branch. None of the new features was tried on a real touch device; long-press was only tried with Chromium's touch emulation.
- **Not done yet:** shape cards and snapshots (see [features.md](../features.md)).
- **A new card can take one or two undo steps.** The history merges a new card with its first text into one undo step, but in the load test a card created on a 1,500-item workspace needed two (the text, then the card) while one on a 500-item workspace needed one. The card was not inside a group in either case; the code merges only when creating changed nothing else, and what changed at 1,500 items was not isolated. Nothing is lost either way, and the load test now allows both.
- **YouTube cards need an internet connection** and are the only part of the app that contacts another site (after you press play). Offline, or with a content blocker, the player area stays blank. Only YouTube links are accepted; other sites are not embedded.
- **Data saved by this version is not readable by older versions.** Canvases and export files now carry version 2, so an older app opens such a canvas as unreadable and keeps a backup rather than dropping the new fields.
- **A locked card is not read-only.** Its position, size, and deletion are protected; its text can still change. Dragging a locked card pans the canvas.
- **Arrange as a tree** lays out the selected cards only and may overlap cards that were not selected; it places a card with two parents under the first parent it reaches.
- **The status ring sits at the corner of a card's box.** On a diamond or ellipse it floats just outside the shape.
- **Checklists** hold up to 40 items of 160 characters; extra items in an imported file are dropped.
- **No PNG/SVG or slide-deck export yet**, and no live collaboration cursors or sharing (these need a server). See [features.md](../features.md).
